# v0.1.0-beta.17

Diese Version kommt aus einem einzigen Anlass: dem ersten vollständigen Lauf
eines Nicht-Technikers über Claude Desktop gegen beta.16, von der Installation
bis zum fertigen Prüfbericht. Alle drei Änderungen sind Befunde daraus.
ELSTER und jede andere Übermittlung ans Finanzamt bleiben gesperrt.

## Der eigene Steuerfall darf jetzt bearbeitet werden

Auf den ausdrücklichen Wunsch „im Original, keine Arbeitskopie“ verweigerte der
Agent bisher und bot einen Umweg an. Das war reine Skill-Politik: die lokale
API hat Originale nie gesperrt. Wer sein eigenes Programm fernsteuern lässt,
muss seine eigene Erklärung auch ändern dürfen.

- **Standard bleibt unverändert** die bytegleich verifizierte Arbeitskopie.
  Für reine Prüfungen wird weiterhin ausschließlich eine Prüffallkopie
  geöffnet — SteuerSparErklärung markiert schon beim Blättern eine Seite als
  ungespeichert, deshalb ist das keine Förmlichkeit.
- **Das Original wird bearbeitet, wenn der Mensch es ausdrücklich verlangt** —
  und erst dann, wenn vier Bedingungen erfüllt sind: der Fall ist nicht
  übermittelt, es liegt kein Wiederherstellungszustand vor, eine
  hashverifizierte Sicherung liegt im Bereich `backups:`, und deren Referenz
  wurde dem Menschen genannt. Ohne bestandene Sicherung wird das Original
  nicht geöffnet.
- **Die Sicherung ersetzt die Verweigerung.** Sie entsteht über denselben
  geprüften Kopierweg wie eine Arbeitskopie (`make_working_copy` nach
  `backups:`, seit beta.16) — mit Quellhash-Pflicht, Readback beider Seiten
  und Rollback bei Abweichung.
- **Die Warnung ist Pflicht, die Rückfrage nicht.** Vor der ersten Änderung
  nennt der Agent in einem Satz: Ziel ist das Original, und dort liegt die
  Sicherung. Nach einem ausdrücklichen Wunsch wird nicht erneut gefragt.
- Der Abschlussbericht nennt **beide Hashes**: den der Sicherung (Zustand
  davor) und den des gespeicherten Originals. Der Rückweg bleibt belegbar.
- Unverändert hart: kein Löschen, kein Umbenennen, kein Überschreiben auf
  Dateiebene, und übermittelte Fälle bleiben unantastbar.

Die MCP-Instructions tragen dieselbe Regel, damit auch ein Agent ohne
geladenen Skill die Sicherungs- und Warnpflicht kennt.

## Ein Navigations-Stopp beendet nicht mehr die halbe Prüfung

Meldete die Prüffallkopie nach dem Blättern `ungespeichert=true`, stoppte der
Lesedurchlauf vertragsgemäß — und ganze Abschnitte blieben ungelesen. Im
beobachteten Lauf traf es unter anderem die außergewöhnlichen Belastungen.

Der Prüflauf wechselt jetzt stattdessen die Kopie: schließen mit
`discardChanges=true` (der Standard-Prüflauf deckt genau dieses Verwerfen ab),
Readback von `stillRunning=false`, Fenstern, Health und beiden Hashes, dieselbe
Kopie erneut öffnen und **nur die noch ungelesenen Abschnitte** lesen. Höchstens
zwei solcher Neustarts; danach endet der Lauf mit einem ehrlichen Teilbericht,
der die ungelesenen Abschnitte einzeln benennt.

## Der PowerShell-Shim von npm verschluckt `--`

`claude mcp add ... -- <command> <args...>` lief unter Windows scheinbar
durch, registrierte aber nichts oder das Falsche. Ursache ist nicht Claude
Code, sondern der von npm erzeugte Wrapper `claude.ps1`: PowerShell entfernt
`--` als Parameterende aus den Argumenten, bevor der Wrapper sie weiterreicht.
Die Installationsanleitung benennt das jetzt, verlangt den Aufruf über
`claude.cmd` oder Git Bash und einen Beweis über `claude mcp list`.

## Unterstützungsgrenze

- SteuerSparErklärung 2025 / Engine-Major 31 bleibt das einzige für Nutzer
  unterstützte Profil (`supported` und `operationAccess=full`).
- Es läuft weiterhin immer nur eine Operation; ein zweiter Aufruf wird sofort
  mit HTTP 409 und `code: "busy"` abgelehnt.
- Der erste sichtbare `launch` erlaubt über die direkte API-CLI weiterhin
  `--timeout-ms 280000`. Das MCP-Tool `sse_launch` behält sein
  Transportbudget von 120 Sekunden; die 280-Sekunden-Aussage gilt nicht
  für den MCP-Transport.
- MCP bleibt ein optionaler, PC-blinder Wrapper über die lokale Loopback-API;
  dieselben Operationen bleiben über die tokenladende lokale CLI verfügbar.
- Noch nie erfolgreich live belegt sind die sechs VaSt-Wege `vast_apply`,
  `vast_dialog_read`, `vast_mapping_options`, `vast_mapping_select`,
  `vast_row_details` und `vast_row_set_expanded` sowie die
  Mehrinstanz-Übersicht `instances`; deren Live-Lauf ist noch nicht als
  Evidenz aufgezeichnet.

Der vollständige Offline-Releaseplan umfasst alle 124 geplanten Schritte:
vier serielle Build-Gates, 117 konfliktfreie Haupttests, einen exklusiven
No-Console-Test und zwei abschließende Abdeckungsbilanzen.

Vor dem Entpacken die separat veröffentlichte
`steuer-spar-erklaerung.zip.sha256` gegen das Portable-ZIP prüfen.
