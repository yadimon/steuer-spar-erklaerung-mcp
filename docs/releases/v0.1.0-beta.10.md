# v0.1.0-beta.10

Dieser Release macht den NPX-Kurzweg ohne MCP zu einem vollständigen Weg: Er
lässt sich jetzt ohne Sackgasse in ein dauerhaftes Setup überführen, meldet
einen belegten Port eindeutig und beschreibt ehrlich, welche Zusagen die lokale
API technisch erzwingt und welche der Prüfablauf der Skills leistet. ELSTER und
jede andere Übermittlung ans Finanzamt bleiben gesperrt.

## NPX-Kurzweg und dauerhaftes Setup verbunden

- Eine vom Foreground-Start erzeugte Konfiguration ist jetzt eine gültige
  Quelle für die einmalige Fall- und Quellbindung. Bisher verlangte der Wizard
  gespeicherte Setup-Entscheidungen, die ein NPX-Lauf absichtlich nie anlegt;
  der dokumentierte Übergang endete dadurch in einer Sackgasse. Eine bereits
  gesetzte, nicht leere Bindung wird weiterhin nie ersetzt.
- `steuer-spar-erklaerung-setup --check` meldet einen reinen NPX-Stand als
  `ok=false` mit `kind="foreground-only-config"` und nennt den nächsten Schritt.
  Vorher las sich derselbe Zustand wie eine kaputte Installation.
- Die Reihenfolge ist dokumentiert und bindend: zuerst die Foreground-API mit
  `Strg+C` beenden, danach das Setup ausführen. Eine noch laufende API lehnt die
  sichere Neubindung wegen abweichendem Konfigurationsfingerprint ab.
- Der erste Start übernimmt eine eindeutig erkannte `SSE.exe`. Damit startet
  auch eine 32-Bit-Installation unter `Program Files (x86)` ohne Setup.

## Belegter Port und gepinnte Paketmarke

- Ein belegter Loopback-Port wird als eindeutige Meldung mit Host und Port
  ausgegeben statt als roher Node-Fehler. Das war der einzige Startfehler, der
  einen Agenten still über eine bereits laufende, anders konfigurierte API
  weiterarbeiten lassen konnte; der Skill verlangt dort jetzt einen Stopp.
- API und CLI werden im Kurzweg auf dieselbe Paketmarke `@beta` gepinnt, damit
  ein zwischenzeitliches Release nicht zwei verschiedene Versionen mischt.
- Die Fallbindung wird über Dateiidentität geprüft: `list_cases` muss den
  erwarteten Dateinamen enthalten und `case_hash` denselben SHA-256 liefern wie
  `Get-FileHash` auf dem bestätigten absoluten Pfad. Die frühere Formulierung
  verlangte eine Prüfung, für die es keine belastbare Rückgabe gab.

## Ehrliche Trennung von API-Zusage und Ablaufdisziplin

- Das Sicherheitsmodell nennt getrennt, was die lokale API technisch erzwingt
  (Loopback und Token, hashgebundene Kopien ohne Überschreiben, byteweiser
  Rücklesetest, ELSTER-Sperre, Abbruch bei mehrdeutigen Fenstern, Pfadblindheit
  des MCP) und was der Prüfablauf der Skills zusagt (Original nicht öffnen,
  Arbeitskopie vor Navigation, kein Speichern in einer reinen Prüfung).
- `--case-dir` ist als Auflösungs- und Schwärzungsgrenze für `cases:`-Referenzen
  beschrieben, nicht als Zugriffssperre. Die direkte lokale API akzeptiert
  weiterhin ausdrücklich benannte absolute Pfade.
- `Standard-Prüflauf ausführen` bestätigt zugleich die Vollständigkeit der
  genannten Belegpfade. Der öffentliche Prüfprompt wird dadurch eine Zeile
  kürzer, ohne eine Rückfrage zu verlieren.

## Reproduzierbares portables ZIP

- Die Einträge des portablen ZIPs werden mit spezifikationskonformen
  `/`-Trennern erzeugt. `Compress-Archive` aus Windows PowerShell 5.1 schreibt
  je nach Windows-Build `\`, was die eigene Archivprüfung zu Recht ablehnt.
  Der Release-Bau hing dadurch von der Windows-Version der Buildmaschine ab.

## Kaltstartvertrag unverändert

- Der erste sichtbare `launch` verwendet über die direkte API-CLI weiterhin
  `--timeout-ms 280000`. Das MCP-Tool `sse_launch` behält sein
  Transportbudget von 120 Sekunden; die 280-Sekunden-Aussage gilt nicht
  für den MCP-Transport.

## Unterstützungsgrenze

- SteuerSparErklärung 2025 / Engine-Major 31 bleibt das einzige für Nutzer
  unterstützte Profil (`supported` und `operationAccess=full`).
- Originalfälle werden nicht geöffnet oder verändert. Sichtbare Navigation
  erfolgt ausschließlich in einer SHA-256-verifizierten Prüffallkopie.
- MCP bleibt ein optionaler, PC-blinder Wrapper über die lokale Loopback-API;
  dieselben Operationen bleiben über die tokenladende lokale CLI verfügbar.
- Noch nie erfolgreich live belegt sind die sechs VaSt-Wege `vast_apply`,
  `vast_dialog_read`, `vast_mapping_options`, `vast_mapping_select`,
  `vast_row_details` und `vast_row_set_expanded`.

Der vollständige Offline-Releaseplan umfasst alle 121 geplanten Schritte:
vier serielle Build-Gates, 114 konfliktfreie Haupttests, einen exklusiven
No-Console-Test und zwei abschließende Abdeckungsbilanzen.

Vor dem Entpacken die separat veröffentlichte
`steuer-spar-erklaerung.zip.sha256` gegen das Portable-ZIP prüfen.
