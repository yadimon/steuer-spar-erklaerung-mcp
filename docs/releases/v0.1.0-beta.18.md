# v0.1.0-beta.18

Diese Version räumt auf. Es gibt ab jetzt **einen** Installationsweg, **einen**
Skill und **eine** Anleitung. Am Produktkern ändert sich nichts: dieselbe
lokale API, derselbe MCP-Wrapper, dieselben 88 Operationen. ELSTER und jede
andere Übermittlung ans Finanzamt bleiben gesperrt.

## Nur noch npm, kein Portable-ZIP mehr

Das portable Release brachte eine eigene `node.exe` im ZIP mit. Das war der
Weg für PCs ohne Node.js — und zugleich ein ZIP mit einer ausführbaren Datei
von GitHub, das Virenscanner und SmartScreen zu Recht anfassen.

- `steuer-spar-erklaerung.zip` und die Sidecar-Prüfsumme entfallen. Neue
  Releases tragen keine Anhänge mehr; installiert wird aus der npm-Registry,
  deren Tarballs der Clean-Install-Smoke ohnehin bei jedem Release beweist.
- Der Build, die vier Portable-Testdateien, die CI-Artefaktschritte und der
  Readback im Release-Skript sind entfernt. Der Offline-Plan umfasst dadurch
  120 statt 124 Schritte.
- **Voraussetzung ist jetzt Node.js 22+ mit npm.** Fehlt es, nennt der Agent
  das als Voraussetzung und stoppt; er installiert keine Laufzeitumgebung auf
  einem fremden Rechner, nur weil jemand seine Steuer prüfen lassen wollte.

## Ein Skill statt zwei

Der Setup-Skill entfällt. Er war nie der Einstieg — bei einem frischen Nutzer
ist gar kein Skill installiert, der erste Kontakt läuft immer über den Link.
Sein Inhalt (Zustimmungsregeln, tokenfreier Merge, Stopps, Reparaturweg) steht
jetzt vollständig in der Anleitung, die der Agent ohnehin liest.

Die Anleitung ist von `skills/steuer-spar-erklaerung-setup/references/` nach
**`docs/INSTALLATION.md`** gezogen und aus dem README verlinkt. Sie ist rund
ein Drittel kürzer als vorher.

## Alles in einem Ordner

Die Anleitung beschreibt genau ein Ergebnis: einen Ordner, der Runtime, Token,
Konfiguration, MCP-Vorlage und Arbeitsbereich enthält.

```powershell
mkdir C:\mein-steuer-ai
cd C:\mein-steuer-ai

npm i @yadimon/steuer-spar-erklaerung-api
npm i @yadimon/steuer-spar-erklaerung-mcp

npx -y skills add yadimon/steuer-spar-erklaerung-mcp --skill steuer-spar-erklaerung --agent codex --copy --yes

.\node_modules\.bin\steuer-spar-erklaerung-setup.cmd --config C:\mein-steuer-ai\config.json --with-mcp
```

Ohne `--global` bleibt auch der Skill im Ordner. Für Claude Code bindet
`claude mcp add --scope project` den MCP-Server als `.mcp.json` daneben; Codex
kennt nur eine globale Konfiguration, kann den Eintrag aber mit
`enabled = false` ruhigstellen und im Ordner per `-c` aktivieren.

`--config` verlangt weiterhin einen absoluten Pfad, weil er in Startern und im
MCP-Eintrag landet. Ohne `--config` schreibt das Setup in den gemeinsamen
Standardort — dann ist der Ordner nicht mehr eigenständig.

## Belegregeln in Prosa

`workspace\settings.md` ist der dokumentierte Ort für Regeln, die eine
Pfadliste nicht ausdrücken kann („dieser Ordner nur teilweise", „Unterordner
Privat nicht lesen", „Kontoauszüge nur für den Zahlungsabgleich"). Der
Hauptskill liest die Datei bei jedem Lauf. Die harte Grenze bleibt
`config.json`: Was dort nicht als Quelle steht, liest die API gar nicht.

## Unterstützungsgrenze

- SteuerSparErklärung 2025 / Engine-Major 31 bleibt das einzige für Nutzer
  unterstützte Profil (`supported` und `operationAccess=full`).
- Es läuft weiterhin immer nur eine Operation; ein zweiter Aufruf wird sofort
  mit HTTP 409 und `code: "busy"` abgelehnt.
- MCP bleibt ein optionaler, PC-blinder Wrapper über die lokale Loopback-API;
  dieselben Operationen bleiben über die tokenladende lokale CLI verfügbar.
- Der erste sichtbare `launch` erlaubt über die direkte API-CLI weiterhin
  `--timeout-ms 280000`. Das MCP-Tool `sse_launch` behält sein
  Transportbudget von 120 Sekunden; die 280-Sekunden-Aussage gilt nicht
  für den MCP-Transport.
- Noch nie erfolgreich live belegt sind die sechs VaSt-Wege `vast_apply`,
  `vast_dialog_read`, `vast_mapping_options`, `vast_mapping_select`,
  `vast_row_details` und `vast_row_set_expanded` sowie die
  Mehrinstanz-Übersicht `instances`.

Der vollständige Offline-Releaseplan umfasst alle 120 geplanten Schritte:
vier serielle Build-Gates, 113 konfliktfreie Haupttests, einen exklusiven
No-Console-Test und zwei abschließende Abdeckungsbilanzen.
