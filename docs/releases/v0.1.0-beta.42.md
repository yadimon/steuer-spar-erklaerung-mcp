# v0.1.0-beta.42

SteuerSparErklärung 2025 mit Engine-Major 31 bleibt das unterstützte
Produktprofil. ELSTER und jede andere Übermittlung ans Finanzamt bleiben
gesperrt. Ebenso unverändert bleiben das Verbot automatischen Speicherns, die
Bindung an einen eindeutig bestätigten Fall, die private hashverifizierte
Sicherung vor dirty-fähiger Bedienung und der unmittelbare Readback jeder
Änderung.

**Diese Version ändert kein Produktverhalten.** Der Operationskatalog, alle
Zeit- und Sicherheitsgrenzen und jede Zusage an den Aufrufer bleiben, wie sie
waren. Sie räumt die Dokumentation auf.

## Die Dokumentation beschreibt jetzt den Code, nicht den Werkstattbetrieb

Die öffentlichen Dokumente hatten sich über die Zeit mit Material gefüllt, das
niemandem nützt, der dieses Repository liest: Protokolle einzelner Prüfläufe,
Namen von Prüfumgebungen, Prüfsummen von Transferarchiven und Messreihen aus
einzelnen Sitzungen. Das ist Werkstattwissen. Es sagt nichts darüber, was der
Code tut, und veraltet mit jedem Lauf.

Öffentlich bleibt, was den Code betrifft: Architektur, API- und MCP-Vertrag,
Operationsreferenz, Installation, der fachliche UStVA-Ablauf, die
Sicherheitsgrenzen und ein knapper Verifikationsstand. Alles andere ist aus dem
Repository verschwunden.

## Zwei Verträge verlangten das Gegenteil

Bemerkenswert genug, um es zu benennen: Ein Vertragstest bestand ausdrücklich
darauf, dass eine Prüfsumme und zwei Zeitstempel aus einem einzelnen Lauf in
einem öffentlichen Dokument stehen. Ein zweiter band eine Offenlegung an eine
einzelne, längst überholte Release-Notiz statt an das dauerhafte Dokument, in
das sie gehört.

Beide prüfen jetzt die Aussage statt ihres Beiwerks: dass der
Verifikationsstand seine Abdeckung nennt und seine Grenzen benennt, und dass
die Architekturdoku die BelegManager-Sperre offenlegt. Die Kennung für einen
Nachweis aus abgeschotteter Umgebung heißt im Abdeckungsledger jetzt neutral
`isoliert`.

## Leistung misst man selbst

Zahlen aus fremden Maschinen versprechen mehr, als sie halten. Statt sie
abzudrucken, nennt der Verifikationsstand die Messwege — allen voran
`npm run perf:api-mega`, das eine vollständige Referenzreise gegen die
installierte Anwendung fährt und Gesamt- wie Einzelzeiten meldet. Wer eine
Änderung bewertet, misst davor und danach auf derselben Maschine, abwechselnd
und mehrfach.

## Zeitgrenzen

Für CLI und MCP-Tool `sse_launch` gilt unverändert eine gemeinsame
Kaltstartfrist von 240 Sekunden; die übrigen Toolbudgets und alle dauerhaften
Sicherheitsgrenzen bleiben operationsspezifisch. Unbekannte Versionen und
unklare Ressourcenbindungen bleiben fail-closed.

## Verifikation vor Veröffentlichung

Der vollständig bestandene Suite-Plan umfasst alle 161 geplanten Schritte,
darunter 148 parallele Haupttests mit konfliktbewusster Worker-Serialisierung
und vier exklusive Windows-Prozess-/Packaging-Gates — einschließlich der
geänderten Verträge und des Abdeckungsledgers. Der Operationskatalog bleibt bei 100
Operationen und 101 Werkzeugen; das Produktprofil bleibt auf Build `31.0.2.0`
nachverifiziert. Das gebaute Paket wurde zusätzlich aus einer frischen
Installation heraus geprüft.
