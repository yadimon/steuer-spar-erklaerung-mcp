# v0.1.0-beta.54

Diese Beta korrigiert widersprüchliche Anweisungen zur ausdrücklich beauftragten
Bearbeitung eines Originalfalls und verbessert die Rückmeldung von `save`.
Unterstützt bleibt SteuerSparErklärung 2025 mit Engine-Major 31. ELSTER und jede
Übermittlung ans Finanzamt bleiben gesperrt. Es kommen keine Operationen hinzu.

## Originalfall und bestehender Auftrag

- Der Originalfall ist der normale Arbeitsfall. Ein früherer
  Übermittlungsvermerk allein sperrt die Datei nicht für weitere Zeiträume.
  Bereits übermittelte Zielzeiträume brauchen einen ausdrücklichen
  Korrekturauftrag. Eine separate Korrekturdatei entsteht nur auf Wunsch.
- Eine klare Freigabe wird für die beauftragten Teilschritte weiterverwendet.
  „Ändere und speichere“ erlaubt beide Schritte ohne zweite Bestätigung.
  Fehlende wesentliche Entscheidungen werden weiterhin geklärt.
- Vor der ersten dirty-fähigen Aktion bleibt eine hashverifizierte Sicherung
  erforderlich. Ein bestätigtes `noChanges` mit unverändertem Disk-Hash macht
  diese Sicherung nicht ungültig.
- Zielbindung, Hashprüfung, Profilprüfung, Readback und die Behandlung
  unbekannter Schreibausgänge bleiben erhalten. Technische Ablehnungen werden
  nicht durch eine Kopie oder einen zweiten Schreibversuch umgangen.

## Verlässliche Save-Rückmeldung

Die Übermittlungswarnung behauptet nur nach einem bestätigten Save, dass
gespeichert wurde. Ein No-op meldet keinen Speicherversuch; ein Fehler bleibt
unbestätigt. `transmittedCaseWarning` gehört jetzt zum beschriebenen
Save-Ergebnisvertrag. Der Ergebnisfeld-Guard erkennt auch PowerShell-Felder,
die mit einer Zeilenfortsetzung an das Ergebnis angefügt werden.

Die Regressionen führen den tatsächlichen Save-/Close-Dispatcher und den
Warnungsblock mit synthetischen Dateiständen und UI-Grenzen aus. Sie prüfen
unter anderem Original-Save mit früherem Übermittlungsvermerk, unbekannten
Status, No-op, fehlgeschlagenen Readback und die optionalen
Korrekturkopie-Bindungen. Ein fehlgeschlagener Schreibabschluss erzeugt keinen
automatischen zweiten Schreibversuch.

## Qualitäts- und Paketvertrag

Die Vollsuite führt alle 262 geplanten Schritte aus, darunter
244 parallele Haupttests mit konfliktbewusster Worker-Serialisierung sowie
sieben exklusive Prüfungen. API- und MCP-Katalog behalten 102 Operationen und
104 Werkzeuge. Quellen, API-Referenz, Skill und gebündeltes Plugin werden
gemeinsam geprüft. API und MCP tragen dieselbe Version; MCP bindet die API
exakt. Der externe Dependency-Graph bleibt unverändert.

`npm run check` verlangt Audit, vollständige Offline-Suite, Plugin-Abgleich,
Release-Metadaten, Produktidentität, Paketprüfungen, Publish-Trockenlauf und
saubere Installation. Der Publish-Workflow prüft den markierten Quellstand
erneut; `npm run smoke:published` prüft die Registry-Artefakte. Für CLI und
MCP-Tool `sse_launch` gilt weiterhin die gemeinsame Kaltstartfrist von
240 Sekunden.

## Bekannte Grenzen

Diese Korrektur ist keine neue reale Abnahme aller Fachabläufe. Synthetische
Save-Prüfungen ersetzen keinen Persistenznachweis am echten Produkt. Die
[bekannten Grenzen von beta.53](v0.1.0-beta.53.md#bekannte-grenzen), darunter
gelegentlich unbestätigtes Menüöffnen, der aktive Tabelleneditor im
UIA-Löschweg und gesperrte BelegManager-Vordergrundoperationen, bleiben bestehen.
Der Cursorleser bleibt ein ausdrücklich gewählter langsamer Fallback.

Qt bleibt optional und ausdrücklich zu konfigurieren. Profil 2024 bleibt
experimentell und auf Verifikation begrenzt. Konto- und Cloud-Abnahmen sowie
eine vollständige aktuelle Dauerabnahme sind keine Zusage dieser Beta.
