# v0.1.0-beta.19

Diese Version entfernt das API-Token — und mit ihm alles, was nur existierte,
um es zu transportieren: den Einrichtungs-Wizard, den MCP-Bootstrap und den
Zwang zu einer Konfigurationsdatei. Am Produktkern ändert sich nichts:
dieselbe lokale API, derselbe MCP-Wrapper, dieselben 88 Operationen für
SteuerSparErklärung 2025. ELSTER und jede andere Übermittlung ans Finanzamt
bleiben gesperrt.

## Kein Token, dafür eine Herkunftsprüfung

Das Bearer-Token sollte verhindern, dass eine Webseite im Browser des Nutzers
die Steuersoftware fernsteuert — `127.0.0.1` erreicht sie ja auch. Gegen andere
lokale Prozesse hat es nie geschützt: Wer auf dem PC Code ausführt, kann die
Konfiguration lesen.

Die API prüft jetzt direkt das, worum es ging, und antwortet mit **403**, wenn

- die Anfrage eine `Origin`-Kopfzeile trägt — Browser senden sie bei fremder
  Herkunft und können sie nicht fälschen;
- sie eine `Sec-Fetch-Site`-Kopfzeile ungleich `none` trägt;
- ihr `Host` kein Loopback-Name ist — das schlägt DNS-Rebinding, bei dem eine
  Seite ihren eigenen Namen auf `127.0.0.1` zeigen lässt und der Browser
  danach ohne `Origin` sendet.

Zusammen mit der schon vorher erzwungenen JSON-Inhaltsart, die ein
HTML-Formular nicht erzeugen kann, bleibt kein Weg aus dem Browser in die API.
Ein lokaler Klient sendet keine dieser Kopfzeilen; ein Browser mindestens eine.

Das sind vierzehn Zeilen statt einer Tokenverwaltung über sechs Module. Live
gegen den laufenden Prozess geprüft: alle drei Wege 403, lokaler Aufruf 200.

## Kein Setup mehr

Ohne Token gibt es nichts zu erzeugen — und damit keinen Grund für einen
Einrichtungsschritt. Ersatzlos entfernt:

- `steuer-spar-erklaerung-setup` samt Wizard, `--defaults`, `--plan-file`,
  `--no-start`, `--check` und `setup-decisions.json`;
- der MCP-Bootstrap `api-mcp-bootstrap.js`, der nur das Token vom
  API-Prozess an den MCP-Prozess reichte;
- die Route `POST /v1/setup/shutdown`, mit der der Wizard eine laufende API
  fernabschalten konnte — ein Fernabschalter ohne verbleibenden Nutzen.

Zusammen rund 66 KB Quelltext in acht Modulen, zwei Testdateien und ein
CLI-Einstiegspunkt.

Installieren heißt jetzt: Ordner anlegen, zwei npm-Pakete und den Skill
installieren, API starten, MCP anmelden.

```powershell
mkdir C:\mein-steuer-ai
cd C:\mein-steuer-ai

npm i @yadimon/steuer-spar-erklaerung-api
npm i @yadimon/steuer-spar-erklaerung-mcp

npx -y skills add yadimon/steuer-spar-erklaerung-mcp --skill steuer-spar-erklaerung --agent codex --copy --yes

.\node_modules\.bin\steuer-spar-erklaerung-api.cmd --config C:\mein-steuer-ai\config.json
```

Der MCP-Eintrag ist eine einzige ausführbare Datei — ohne Argumente, ohne
Umgebungsvariablen, ohne `--config` und ohne `--mcp-entry`:

```powershell
codex mcp add steuer-spar-erklaerung -- C:\mein-steuer-ai\node_modules\.bin\steuer-spar-erklaerung-mcp.cmd
```

## Die Konfigurationsdatei ist optional

`config.json` muss nicht mehr existieren. Der erste Start legt `workspace\`
mit `documents\`, `results\`, `backups\` sowie `logs\` an; `--config` benennt
nur noch, wo der Ordner liegt. Nötig wird die Datei erst für einen
abweichenden Port, ein festgepinntes `sseExecutable` oder einen festen
`caseDir`.

Eine ältere Betakonfiguration mit `token` wird nicht stillschweigend
ignoriert, sondern beim Start mit einer Meldung abgelehnt, die die zu
löschende Zeile nennt.

## Ein Skill, der zuerst nach dem Transport fragt

Der Hauptskill beginnt jeden Auftrag mit genau einem `sse_health` und
entscheidet daraus ohne Rückfrage: API läuft, API läuft nicht, oder es gibt
gar kein `sse_*`-Tool. Im letzten Fall wechselt er in den Einrichtungsmodus,
arbeitet die Anleitung ab und liest bis dahin keine Steuerdaten.

## OpenAPI ohne Sicherheitsschema

`/v1/openapi.json` deklariert kein `bearerAuth` mehr, und die
`401`-Antworten der Operationen sind `403`. Generierte Klienten bekommen damit
kein Anmeldefeld mehr aufgedrängt, das es nicht gibt. Die drei
selbstbeschreibenden Endpunkte bleiben der einzige Vertrag:

```powershell
curl.exe http://127.0.0.1:43127/v1/openapi.json
curl.exe http://127.0.0.1:43127/v1/operations
curl.exe http://127.0.0.1:43127/healthz
```

## Weitere Aufräumarbeiten

- `createSseApiServer` nimmt keine `config` mehr entgegen: Der HTTP-Kern
  brauchte sie nach dem Wegfall der Tokenprüfung an keiner Stelle mehr.
- Die Erkennung der installierten `SSE.exe` ist von `setup.ts` zu ihrem
  einzigen Nutzer gewandert.
- Stale gebliebene Namen aus dem entfallenen Portable-Release sind aus dem
  Testplan verschwunden.

## Unveränderte Grenzen

- Es läuft immer nur eine Operation je API; ein zweiter Aufruf wird sofort
  mit HTTP 409 und `code: "busy"` abgelehnt.
- MCP bleibt ein optionaler, PC-blinder Wrapper über die lokale Loopback-API;
  dieselben Operationen bleiben über die lokale CLI verfügbar.
- Der erste sichtbare `launch` erlaubt über die direkte API-CLI weiterhin
  `--timeout-ms 280000`. Das MCP-Tool `sse_launch` behält sein
  Transportbudget von 120 Sekunden; die 280-Sekunden-Aussage gilt nicht
  für den MCP-Transport.
- Noch nie erfolgreich live belegt sind die sechs VaSt-Wege `vast_apply`,
  `vast_dialog_read`, `vast_mapping_options`, `vast_mapping_select`,
  `vast_row_details` und `vast_row_set_expanded` sowie die
  Mehrinstanz-Übersicht `instances`.

## Verifikation

Der vollständige Offline-Releaseplan umfasst alle 119 geplanten Schritte,
davon 112 konfliktfreie Haupttests. Die Herkunftsprüfung ist zusätzlich live
gegen den gestarteten API-Prozess belegt, nicht nur gegen einen Testserver.

Unverändert gilt: nur Windows x64, nur SteuerSparErklärung 2025 mit
Engine-Major 31, Node.js 22 oder neuer mit npm.
